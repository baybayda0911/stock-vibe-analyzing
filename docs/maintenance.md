# 文档、扩展与版本维护

## 多 Skill 目录规则

`stock-vibe-analyzing`是股票分析Skill集合，每个Skill位于`skills/<skill-name>/`，名称与frontmatter一致。基本面与技术面形成专业研究，研究室回顾旧判断、原因及反馈，档案室定位／比较／导出和恢复已有文件。当前技术面实现常规、蜡烛、一目、谐波、SMC和海龟六个有限专题，聚焦日／周／月／半年／年线；分钟、缠论和两个波浪暂停。研究室实际档案、技术报告／数据／图表和档案室生成页面／快照／恢复副本不纳入源码或安装包。

每个 skill 必须能独立复制、安装，包内入口、元数据、参考资料和脚本相对引用自包含，不硬依赖仓库根文件或相邻 skill。外部工具需求须明示：档案室复用既有研究室协议，由宿主显式提供已核验的`research_lab.py`绝对位置并传`--lab-tool`；不能扫描猜测安装目录，工具缺失就说明未执行。避免为了共享少量文字引入跨 skill 依赖，只有实际重复和维护需求出现时再设计共享机制。

| 内容 | 唯一维护位置 | 同步规则 |
|---|---|---|
| 仓库说明与 Skill 清单 | 根 `README.md` | 新增、移除或更名 skill 时更新 |
| 仓库整体版本 | 根 `VERSION` | 同步 README、CHANGELOG 的仓库版本记录 |
| 各 Skill 的触发、执行流程与自身版本 | `skills/<name>/SKILL.md` | 名称与目录一致，版本写入 `metadata.version` |
| 各 Skill 的展示与调用策略 | `skills/<name>/agents/openai.yaml` | 示例调用与入口名称一致 |
| 各 Skill 的研究依据 | 该 skill 的 `references/` | 入口保持引用完整，不复制到根目录维护 |
| 档案室协议、工作区与恢复边界 | `skills/stock-research-archive/references/档案室说明书.md` | `docs/research-archive.md`导航安装与职责，不另建存储协议 |
| 本地工作台启动、操作与范围 | `docs/platform.md` | README导航；同步S4双来源任务、问题／取消／恢复，以及S5同口径只读比较、冻结材料与补充角色；实际能力仍独立验收，历史探针不代替当前执行能力 |
| 统一更新记录 | 根 `CHANGELOG.md` | 标明受影响 skill、其版本和迁移要求 |
| 维护约束与验证 | `AGENTS.md`、`docs/` | 如实区分结构检查和实际行为测试 |

基本面 skill 的 `references/prompt.md` 保留原 TXT 十项研究目标，`references/公司研究框架.md` 是持续维护的完整框架：当前为十一专题、十章报告，统一指标口径集中在4.5节，行业周期与定价完整规范位于专题十，报告第9章仅引用交付要求。原文 V3.0 是提示词历史标记，不用于判断项目或 skill 的更新版本。

生成报告、持仓和下载资料不进入公开仓库；研究室正式档案只写用户确认的仓库外根，不把源码内被忽略目录当归档回退。本机同步记录、备份、代理和个人笔记留在仓库外。新增可执行脚本时才引入必要依赖和有效测试，有真实可运行检查后再考虑CI。

档案室保持同一私有根、一套原始记录与一个可重建catalog；首页、比较及资料包只作阅读副本。私有根内使用`_workspace/views`、`_workspace/backups`、`_workspace/restore-tests`，工作区排除在正式记录扫描和快照源之外，不复制维护第二套台账。`backup`生成完整文件快照，`verify`核对清单与指纹，`restore`仅写新目录并重建索引；同盘副本不构成硬盘故障容灾。独立包的三个脚本为`research_archive.py`、`archive_views.py`及`archive_backup.py`，随包共七资源。

技术面数学规则、数据口径和读图以包内`references/技术面分析说明书.md`为主，谐波细则另见同目录专题说明。常规主后端固定TA-Lib及其暖启动语义；依赖只在独立环境按`requirements.txt`准备，不改其他项目的基础环境。标准库隔离帮助、完整数值、可得时点、真实图表和数据资格各自检查，不能互相替代。

新增数据字段必须同步适配、规范化、计算和输出。`mechanical_gap`／`session_id`等显式声明不能在读取中丢弃；SMC跨已声明边界的FVG／订单块排除要有实际回归。原价、来源或机械原因未核验仍是诊断，不能只靠免责声明提升资格。多个周期由同一源派生时保留共同同源组，不作为独立投票。

默认周期为`1d`／`1w`／`1mo`／`6mo`／`1y`，分钟入口保持`paused`，不读取、取数、计算或聚合；保留旧档与历史兼容函数不等于恢复分钟研究。半年／年须有完整日历覆盖，仅计算最近连续完整段，并保留断段、未完成期、缺尾期及真实`data_asof`。不填停牌日、不跨缺期凑暖启动、不借长周期聚合提升复权资格。

自建申万行业组合统一标明非官方指数，保留逐日归属、分类可知性、前收参考价收益、等权方式、覆盖率、缺数、链段及目标股依赖。不得将当前成分静态回填后声称历史当时已知，也不因参考外部平台而增加其运行依赖。默认简明HTML／Markdown与`details`附录共享同一计算结果；正文保留结论、理由、主图和后续条件，专题方法与全图放附录，不增加同源票数。

## 本地工作台S5维护边界

0.16.0沿D5保留四主入口、个股科目页及Codex／DeepSeek双来源持久任务，保留2—5股共同口径只读比较，并完成S1—S5验收修订。启动／操作唯一维护于[平台说明](platform.md)，实际测试、两股及浏览器证据只在[验证记录](validation.md)登记。标准库HTTP服务保留Host、会话、Origin／CSRF、路径、身份、日期和指纹校验，不增加Web框架；可选PyMuPDF只在已安装时提取PDF，不自动安装。真实路径、凭据、日志与专属项目标识留私有区。

dashboard.py、fundamentals.py投影已识别原档；完整底表和最近增量按来源／财务期／覆盖组成，不拿mtime或较晚取得时间全盘替换。现金使用合并利润分母，单季由累计金额差分，毛利率由对应金额重算；TTM／股数／股类／币种及A/H等值估值不得混合。历史图和原情景不因重绘变成新结论。价格图取真实所选周期最后60根观察，蓝色价格和金色虚线MA5有图例、起止日期、变化；原价／参考链仍按原资格，缺口不连线，旧项不抹去。

analyst_sources.py读取显式资料根下的固定证券研报索引，原发布日期、封面日、实际检查／取得／提取分别保留；未知精度不补零点。稳定线索身份不受入库／抓取或mtime变化影响，正文未取不生成观点／预测；预测财年不随系统年份滚动，不将券商EPS自动并入当前估值。

broker_cache.py只在明确动作下有限获取允许公开来源、核PDF与身份／指纹，并在私有_workspace/platform/broker-cache写source-only缓存及索引检查快照。暂存本身不形成正式成果、不进入完整快照；用户另行明确归档时由broker_archive.py登记原件及broker_source补充成果，原发布日期、封面日、取得／提取与归档时间分开。仅原件保存而适配未完成须标partial，按原ID续作，不宣称完整归档。合法source_ref将注册原PDF及import.json纳入对应成果导出，原imports也进入既有快照/2与新目录恢复；工作区缓存继续排除。公开原件可访问不等于可随MIT代码再分发。

正式研究选择统一复用`stock-research-role-resolver/1`：完整、增量及更正研究参与正式选择，broker_source／source_adaptation为补充事件，unknown不猜测。正式研报归档的兼容门槛核对明确配置的Codex与Trae两处安装位置、共同角色能力和各34资源的指纹；不能只靠页面过滤绕过旧宿主。此前S3两端曾备份旧版后更新并核验；本轮已另行备份并对齐双端技术0.5.0安装，后续安装变化、资源缺失、指纹或角色能力不符仍须关闭入口。这是当前配置的验证，不保证所有宿主或未来版本持续兼容；Trae本轮未重做对话验证，也不保证已打开客户端热加载新技能。

可信新股身份、无档空态、异步切股隔离和页面内草稿保持；保留草稿不执行，不创建正式成果。明确开始才创建持久任务，固定完整证券、日期、来源、方式和范围；切股只改变当前看板，不改后台任务。名单唯一持久路径platform/watchlist.json继续与研究室同锁原子写，移出不删研究。任务、尝试、冻结输入、恢复状态及缓存只写固定私有工作区，不扩大为任意文件写入或访问，也不纳入正式档案快照。

S3的continuity.py遍历全部冻结旧项、回顾和明示规则，输出证据覆盖、原观察窗口、候选及下一步队列；continuity_actions.py只在用户明确提交、理由和版本标识有效时追加保守回顾，不改原判据。观察和历史重建不冒充事前预测，不计算命中率或收益；已保存但看板回读失败须明确“已保存、勿重复提交”。

双来源仅为既有Codex执行和DeepSeek API，共用受限Codex执行能力；不增加独立OpenAI API Key路径或任意shell执行器。两来源各自持久线程核同一已确认的专属项目身份及cwd，不改原HOME、现有登录或全局模型配置。进程内命名权限配置的文件矩阵已实测只读指定attempt、拒绝越界读与全部写入；网络禁用仅核实际配置，未做独立连通探针，MCP、命令等模型工具禁用；平台托管材料读取、数值／图表继承、校验和归档。执行或恢复前仍重核实际权限、来源和项目，不能只靠提示词，矩阵通过也不代替真实研究质量或完整流程验证。

S4模型任务依可信冻结档案和原组件生成报告，不主动Web／Wind取数、后台更新行情或重算专业指标；P1本地预览与确认重算走独立入口。完整研究缺量化材料时保留问题卡，不能凭常识补数或冒充完整首研；旧财务、行情、估值、计算截止与本次真实生成时间分开。研报驱动只接收已核正文且正式归档的补充来源，本版broker_update一律source_adaptation，不更新正式基本面主角色；已完成任务的资料引用标签不表示全部观点已采纳。

research_tasks.py负责稳定请求身份、状态及修订令牌，research_provider.py负责受限来源与原线程核验，research_materials.py负责冻结材料、输出校验及原工具追加归档。读取页面、重开服务或不确定网络响应不能触发自动付费重跑。问题绑定原任务和原问题，取消保留已有成果，恢复先核原turn与已有产物、只补所缺；费用未知保持未知，已消耗不能撤销。归档提交中不可取消，正常停机等待完成。原档和已归档部分不因取消、失败或新任务改写；无新输入不得悄悄抬升材料截止。

comparison.py复用正式研究投影，比较2—5个完整证券在共同观察日可见的事实，按年初至今累计／单季／全年选共同财报期并统一人民币元。营收及归母盈利同比使用上年同期间可信金额，销售毛利率按合并收入成本，现金转化率分母为同期合并净利润；期末应收和库存标明余额，缺数、非正分母与冲突不转0。名义原价必须同口径、同窗和共同N+1价格点才作基100诊断；股本／股类、TTM、原情景及各自技术价格链不兼容时保留不可比原因，不用单一总分排名。

比较请求冻结证券、观察日、期间及价格窗，来源和各自财务／行情／生成日期分别返回；不调用模型／Wind、不重算专业技术指标、不改原档、旧项或名单。新版比较引擎、已有独立真实比较和虚构评审稿分开验证。源码、权限矩阵、真实两股／页面执行、全局安装及公开发布分别登记，不预写通过数或比较结论；布局偏好、备份恢复及其它增强仍依实际范围单独交付。

源码白名单105文件，app二十二文件加通用启动入口共二十三必需运行资源；四独立技能按基本面／研究室／技术面／档案室分别6／6／15／7，共34资源。当前版本为基本面0.3.2、研究室0.3.0、技术面0.5.0、档案室0.3.0。档案室0.3.0沿用含可选名单的快照/2，兼容读旧/1；正式注册原件及导出范围单独验证。broker-cache不在快照源，不能把暂存说成完整备份或同盘副本说成异盘容灾。

## P1本地更新维护边界

本地更新的幂等身份必须绑定实际可纳入的行情末日、财务可见版本及可选基准末日，不仅绑定原CSV指纹；实际读取时间不作为每次新增的理由。会话完成或公开日跨越后，源文件即使未变也需按新的有效选择生成独立快照，原冻结字节保留。真实后端的暖启动不足保留缺失，不等于依赖不可用。任务状态读写共用锁，Windows短暂共享错误仅有界重试；持续无法写入时保留原状态，解除原因后须明确重试或重启恢复，不删原研究。

本版新增用户显式触发的“预览本地数据→确认更新与重算”。从已配置的财务、原价日线及日历源一次读取并冻结指纹，核证券、期间、单位、公开日与实际取得时点；预览不归档，确认后才复算并追加独立财务数据专项及完整技术成果，旧报告和原文件不覆盖。这不是自动下载新披露或启动模型，也不把财务专项当作全公司商业模式和估值观点已经更新。读页面、切股及只读比较仍不取数。

周／月／半年／年的自然期间定义保持，但有完整计划日历与有来源的最后会话结束映射时，按该期间最后交易会话确认完成，不再一律等到自然周日末。`calendar.session_closes`须与`trading_dates`一一对应，并保留来源、会话来源和实际可得时点。2026常规休市安排逐日匹配可形成独立验证窗口，其他历史和未来计划不随之认证；整体`calendar.verified=false`与每期间的`latest_period_completion_verified`分别说明。15:30为已引用规则支持的全天量额保守完成上界，不伪称逐日实际成交秒时刻。原价／权息、交易日历、会话、资料可得及指标用途各自核验；周期完成通过不把原价升级为认证复权或执行信号。

本轮技术Skill升0.5.0，基本面0.3.2／研究室0.3.0／档案室0.3.0保持。按既有双端更新授权，已备份后对齐Codex和Trae的技术安装，并核每端34资源及既有角色兼容门；其他Skill文件保持。此为文件／能力核验，不代表已打开宿主热加载或Trae新对话通过。后续资源变化、缺失或旧工具不兼容仍须关闭新的研报正式归档门，不能放宽指纹门槛。源码、安装、数值重算、页面、Git及Release分别记录。

本地适配由local_financial.py、local_market.py和local_updates.py分别核字段／时点、行情／日历和受控执行。三份对应测试同步白名单；缺数、冲突和失败／部分归档不得伪装完整更新，重试使用既有记录身份补所缺。无分钟、Wind、模型调用、依赖安装、后台调度或任意路径执行器。实际两股及回归结果只记验证文档，不预写成功数量。

## 新增下一个 Skill

1. 明确用途与触发范围，先检查已有 skill 能否满足；专业研究、旧判断回顾与档案文件管理分别定义入口。
2. 创建 `skills/<name>/SKILL.md`，设置英文 `name`、清晰的 `description` 和初始 `metadata.version`；按需添加元数据、参考资料或真正必要的脚本。
3. 确认单独安装后的包内引用完整，外部工具依赖明确配置；不能把读取相邻 skill 当作默认前提，需要组合研究时由用户任务选择相关能力。
4. 更新根 README 清单、CHANGELOG 与对应验证用例，标明哪些能力已实现、哪些仍在规划。
5. 完成结构、安装包与实际相关行为验证后，再按授权安装或发布。

## 本轮验收修订的维护边界

视图偏好只在本浏览器同运行地址保存可信身份、页面／科目及图表／比较条件，不作为正式源记录或快照内容；随机端口改变不保证恢复。只恢复视图，不重放比较、研究或未提交草稿。档案关键词使用已加载标题、概述、来源及ID元数据的AND匹配，并结合模块／日期筛选；不要为此读取PDF正文或新增未经授权的检索服务。

延续旧项超每模块50条时先明确分批，任务准入及冻结材料两处共同挡在模型调用之前，未选旧项继续保留。页面保守回顾不得把历史current_use改成needs_review；事实资格、原期限与状态分别核验。真实两股验收和模拟边界测试分开登记，不用0机器候选冒称预测验证成功。

## 两级版本规则

仓库与各 skill 分别采用 `MAJOR.MINOR.PATCH`。仓库版本只存于根 `VERSION`，skill 版本只存于其 frontmatter 的 `metadata.version`。README 是导航展示，CHANGELOG 是历史记录，不再为每个 skill 复制 VERSION 或 CHANGELOG。

| 对象与变更 | 规则 | 示例 |
|---|---|---|
| Skill 修正文案、失效链接或错误，主要触发和输出兼容 | 增加该 skill 的 PATCH | 基本面 `0.1.0 → 0.1.1` |
| Skill 新增重要能力；0.x 阶段出现不兼容变化 | 增加该 skill 的 MINOR，PATCH 归零 | 基本面 `0.1.1 → 0.2.0` |
| 单个 Skill 经过验证并由维护者确认稳定 | 该 skill 升为 `1.0.0` | 不要求其他 skill 同时稳定 |
| Skill 在 1.0.0 后不兼容地改变名称、输入或核心输出 | 增加该 skill 的 MAJOR | `1.2.0 → 2.0.0` |
| 仓库仅含兼容修复或公共文档调整 | 增加仓库 PATCH；未改动 skill 不升版 | 仓库 `0.1.0 → 0.1.1` |
| 仓库新增 skill、增加重要能力，或 0.x 阶段发生不兼容调整 | 增加仓库 MINOR | 新增技术面 skill 后仓库 `0.2.0` |
| 仓库达到稳定集合约定并经维护者确认 | 仓库升为 `1.0.0` | 以后不兼容集合约定提升 MAJOR |

例如：新增技术面 skill 初始为 `0.1.0`，仓库可从 `0.1.0` 升到 `0.2.0`，未修改的基本面 skill 仍为 `0.1.0`。若只修复基本面 skill，提升其 PATCH，并相应提升仓库 PATCH。

同批变更取适用的最高级别；只改仓库外笔记不升版。当前仓库0.16.0、基本面0.3.2、研究室0.3.0、技术面0.5.0、档案室0.3.0；最近GitHub Release仍0.1.0，源码提交及标签推送另行核验。本次增加P1受控本地更新与交易会话周期完成，仓库按MINOR升0.16.0，技术Skill按MINOR升0.5.0，其他三个Skill版本保持。此前S3两端安装的备份及34资源指纹核验有独立记录；本轮技术安装另按既有授权备份并同步双端、核每端34资源与角色兼容门。文件核验不替代宿主新会话加载或自然语言调用测试。已发布版本不可原地替换，预览版可用`0.16.0-rc.1`等后缀。

## 更新与发布顺序

1. 读取变更涉及的入口、资料、调用示例与用例；只修改有实际需要的 skill，保留用户已有工作。
2. 更新唯一来源，并在 CHANGELOG 的 `Unreleased` 下按 skill 归属记录新增、修复、兼容变化和迁移方法。
3. 按 [验证文档](validation.md) 检查结构、资源、触发边界和相关行为。记录实际覆盖范围，不能用结构通过替代完整研究验收。
4. 准备版本时更新受影响 skill 的 `metadata.version`、仓库 VERSION、README 与 CHANGELOG；不要求无变化 skill 跟随升版。
5. 在隔离目录按 README 验证选定 skill 的复制安装，确认包内引用完整、外部工具依赖已显式配置；实际用户级更新前核对目标并备份旧目录。
6. 准备公开版本前确认新增资料来源与许可，保留根目录及各独立分发包的 MIT 声明；按本机规则完成独立文件安全检查，报告后停止，该阶段完全不运行 Git。
7. 后续取得明确 Git／发布指令后，核对实际待提交内容，再提交、创建对应仓库版本标签、按授权推送并发布 Release。

发布包使用[逐文件白名单](../release-files.txt)和[归档核验](releasing.md)，不以忽略规则代替实际提交树与附件核验。当前105源文件，app二十二文件、通用启动入口、说明及相关平台测试逐件列入；独立6／6／15／7共34，不夹带运行状态或研报暂存。增删资源同步清单、构建脚本与检查，历史验证保留原时点数量。

外部Skill／数据工具可能在正常调用前触发自动更新、全局状态写入或Git检查。实施前核对钩子范围，实施后记录实际副作用和代码指纹；不要只因主脚本未主动调用Git，就断言全流程无间接Git。历史Wind钩子的实际边界见[验证记录](validation.md)，本机路径和原始日志留管理资料。

Git 标签 `v0.1.0` 标记整个仓库快照；Release 列出包含的 skill 及各自版本、升级方法、兼容性和验证边界。暂不引入每个 skill 独立的标签体系。

首次接入远程时，通过 Git 克隆建立关系，核对其内容与历史并备份本地资料，不擅自合并两套历史。经授权维护 Git 时，使用已核实的远程默认分支（当前为 `main`）；较大修改可用 `feat/<主题>`、`fix/<主题>` 或 `docs/<主题>`。提交前核对身份与选定内容，推送前核对目标及待推送提交。文件编辑、全局安装、Git 提交、标签、推送与 Release 均按各自授权执行。
