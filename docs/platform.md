# 本地研究工作台使用说明

适用本仓库0.16.0／P1，配套技术面Skill为0.5.0。沿D5保留研究工作台、个股研究、横向比较、档案室四个主入口；个股内分研究总览、基本面、技术面、判断验证。本版新增受控读取本地财务、日线和交易日历，明确确认后重算并追加归档；打开、切股和比较不调用模型或自动重算。“开始研究”发起专业研究任务，“重算并保存新快照”发起独立的本地数值更新，两者分开。

**本版研究以平台核过的冻结档案和组件为依据。** 本地更新只读取已配置的数据文件，不主动进行Web／Wind取数；实际读取时间、源文件版本、财报所属期和行情末端分别保留。无新披露时不称“财报更新”，新生成日期也不等于新财报或新行情。材料不足时要求补充，不能把无数据的短文冒充完整首次研究。源码能力、真实执行、权限隔离、全局安装与发布的实际范围分别见[验证记录](validation.md)，本说明不预写验收结论。

程序核心使用Python 3.10+标准库和浏览器，不增加Web框架。研报PDF文本提取可用已安装的PyMuPDF；缺失时保留正文待提取，不自动安装。完整技术重算的NumPy／TA-Lib等仍属于原技术Skill环境，查看已有档案不要求这些依赖。

## 1. 准备与启动

| 位置 | 用途 |
|---|---|
| 仓库目录 | 当前app、配套skills和通用启动入口 |
| 私有档案根 | 已经研究室初始化、位于Git外、不经链接的绝对目录；沿原正式档案，不复制第二套 |
| 专属项目目录 | 已有绝对目录；不等于后台Codex项目身份 |
| 可选证券CSV目录 | 读取固定证券头部身份；同一资料根按固定目录读取研报线索、本地财务、交易日历和可选沪深300，不扫描其他磁盘 |

新环境先按[研究室说明](research-lab.md#初始化私有根)初始化已确认私有根。启动平台不自动初始化、迁移、导入旧报告或修改模型认证。研究室工具默认使用本仓库配套脚本；显式更换工具时用--lab-tool传已验证的绝对路径，不将陌生脚本作为配置加载。

执行研究还需要本机已有Codex可执行程序、专属项目的真实后台身份，以及可用的来源认证。私有`_workspace/platform/research-engine.json`保存明确的程序位置、项目目录／身份和DeepSeek凭据入口；页面只展示配置状态，不填写、下载或回显密钥。配置缺失或运行约束未核对成功时不开始研究，不自动安装、登录或修改Codex全局设置。Codex沿现有账户；DeepSeek使用独立配置，两者不能在恢复时互换。不提供另一个OpenAI API Key模型路径。

在仓库根打开PowerShell：

    $archiveRoot = Read-Host '私有档案根的绝对目录'
    $projectDir = Read-Host '专属项目的绝对目录'
    python -X utf8 -B app/launch.py --root $archiveRoot --project-dir $projectDir

Windows也可运行start-platform.cmd并传相同参数。指定已有证券目录时：

    $marketDir = Read-Host '已有本地证券CSV的绝对目录'
    python -X utf8 -B app/launch.py --root $archiveRoot --project-dir $projectDir --market-data-dir $marketDir

两个位置也可从STOCK_RESEARCH_LAB_ROOT、STOCK_RESEARCH_PROJECT_DIR读取，显式参数优先。真实路径不写入公共仓库。--no-browser只启动／核对并输出状态；再次正常启动可打开已认证页面。

### 1.1. 启用本地数据更新

先以`--market-data-dir`明确指定已有的`stock-trading-data-pro`目录。其同一资料根须有以下固定来源；本版更新入口仅支持已确认完整身份的沪深人民币A股一般企业，不自行推断其他报表类型或扫描数据盘。

    DATA_ROOT/
    ├── stock-trading-data-pro/<交易所前缀><代码>.csv
    ├── stock-fin-data-xbx/<交易所前缀><代码>/<交易所前缀><代码>_一般企业.csv
    ├── period_offset.csv
    └── stock-main-index-data/sh000300.csv       可选沪深300背景

在已初始化私有根的`_workspace/platform/local-data-config.json`保存以下**完整且仅有三项**的配置。`technical_python`须替换为本机已有技术计算环境中Python程序的绝对路径；下例是占位路径，不能直接运行，不在公开仓库写真实私人路径。

```json
{
  "schema_version": "stock-local-update-config/1",
  "enabled": true,
  "technical_python": "X:\\example-technical-runtime\\Scripts\\python.exe"
}
```

该环境须已有技术Skill所需NumPy、TA-Lib等依赖。程序核对明确路径及可执行文件，不查找或安装新环境，不接受网络路径或额外配置项。配置缺失、不兼容、源文件缺失或证券不支持时，更新入口说明原因，原有研究仍可查阅。变更配置后正常停止并重开服务。

服务只监听127.0.0.1，自动选择端口；启动器打开含临时访问凭据的入口，不要把旧裸端口固定为书签。重复打开核身份并复用当前服务。升级或变更配置须正常停止旧服务后启动当前版本，不能把旧进程当新参数已生效。已有本机Quant开停入口继续指当前源码，不必修改路径。

## 2. 确认研究对象

在顶部输入名称、代码或完整证券ID，查找后从候选确认市场、交易所、代码、股类、币种。候选来自原档、名单和已配置CSV，不凭裸代码猜市场或捏造新公司。

CSV只接受明确sh／sz／bj前缀，文件名和头部代码必须一致。裸六位代码只检查实际存在的三个交易所候选文件；名称可能来自历史首条记录，明确标“本地历史名”。正式归档名称优先，名单简称只有其他六身份字段一致才兼容，不重写原名单或报告。首次模糊名称检索可能较慢。

无档证券显示独立空态，不沿用前一只公司的曲线、判断或日期。确认身份后可准备首次研究草稿；加入关注与形成研究成果分开。切换页面保留当前股，“重新载入已有研究”重新读取原档，不发起研究或刷新行情。

## 3. 按D5进入日常研究

四个主导航为研究工作台、个股研究、横向比较、档案室；任务和设置是辅助入口。选定证券后，个股研究内切换研究总览、基本面、技术面、判断验证四个科目。

| 页面 | 本阶段可用内容及边界 |
|---|---|
| 研究工作台 | 跟踪公司、真实价格走势、基本面／技术面独立列和跨历史的下一步关注；检查时间不是研究更新时间 |
| 个股研究总览 | 同股经营、技术摘要及与研究室一致的下一步队列，回到科目和原报告 |
| 基本面 | 历史＋增量指标、年度／季度A图、现金、原估值情景和研报补充；可受控更新财务专项数值，原公司观点单独保留原日期 |
| 技术面 | 五周期归档K线、量能、MACD／RSI、均线和原资格；可从冻结本地日线重算并保存新成果 |
| 判断验证 | 跨历次成果的原判断、冻结／观察窗口、后续证据与覆盖、检查状态、正式回顾及下一步；支持筛选和保守人工回顾 |
| 横向比较 | 2—5股共同观察截止、累计／单季／年度同期间比较；经营、现金、估值、价格与原技术判断分列，可比性、缺口及来源可追溯 |
| 档案室 | 原成果、回顾及正式补充研报，按模块和研究／原发布日期筛选；暂存研报不冒充正式档案 |
| 任务／设置 | 跨证券的持久任务、实际阶段、补充问题、取消／恢复及来源可用状态；不展示聊天记录或密钥 |

### 3.1. 价格走势与技术图

首页默认最近60个已归档日线观察。**蓝色实线为价格，金色虚线为MA5**；图例、真实起止日期和窗口变化同时展示。日／周／月／年分别使用该周期收盘与MA5，不能套用日均线。

从左到右按由早至晚排列，取所选周期最后的观察窗口，依据真实数值绘图。可用起点、终点、区间变化及原JSON核对趋势。D5虚构示意曲线不作为正式数据；K线红绿只表示单根收盘相对开盘，不代表整段涨跌。

技术图支持日／周／月／半年／年，均线MA5／20／60／120，副图MACD或RSI14。悬停或聚焦后左右键联动数值；根数、历史窗口或Ctrl＋滚轮只改变显示，不重算专业结论。缺数、未完成期、断档和暖启动不足保留；MA5先在完整合格周期上计算再切窗，其他指标沿归档值。

本地重算的周／月／半年／年线按声明交易日历寻找该期最后一个交易会话，在该会话完成且所需日期覆盖通过后才纳入。当前仅将本地2026年常规交易安排与已公布日期逐日核对，跨出该窗口、缺日历、缺行情或无法证明完成时保留限制，不将周五日期本身当作完整交易周的证据。日线采用北京时间15:30作为全天量额的保守完成上界；它不是逐日实际发布时间，也不能代表所有历史市场的会话规则。

页面“完成期已核”仅指所选周期及声明窗口通过核对；没有该声明时显示“未认证／见来源”。旧报告和旧计算不改写，原自然周日保守口径仍按原来源阅读，不能给旧成果追授新认证。

价格基础、所选周期资料末端、研究截止、报告／计算生成分列。raw或未认证参考链仍为诊断；打开、切图和重载不提升复权、日历或执行资格。原报告、历史与完整限制保留在可展开区域。

### 3.2. 基本面可视化看板

从已识别完整研究及增量组成看板：长历史来自原底表，最近单期事实、现金或估值覆盖须有明确来源；不按mtime或取得时间全盘替换。未知／冲突模式说明缺口，不静默取任意最新文件。

指标区分累计、单季及TTM，展示单位统一转换。归母利润与合并利润不互换。现金转化率＝经营现金流／同期合并净利润；简化自由现金流＝经营现金流－购建长期资产现金，不等于可分配股东现金。单季从累计金额差分，毛利率按相应单季收入及成本重算，不直接对毛利率做差。

年度／季度按钮切换A版分面：上图营收／归母柱图及原价格／PE序列，下图利润增速与销售毛利率。财报所属期不等于该期末已公开，历史PE及价格基础按来源阅读；缺失或不可比不补线。现金图观察利润与现金是否同步。

定价区沿用原报告明确的悲观／基准／乐观假设、时间和来源，不生成新目标价。不同股类、股数、币种或盈利分母不兼容时提示；券商EPS不自动进入平台估值。原财务期、公告日、研究截止和生成时间分别保留，展示不使旧情景自动续期。

本地财务重算形成“财务专项快照”，只更新有来源的财务底表与计算，不能冒充重新研究公司商业模式或投资价值。看板独立标注所沿用完整公司研究的ID和原研究日期，并提供“阅读旧公司研究（未更新）”；本轮生成日期不替旧观点续期。股本／股类口径未统一时不重算PE或目标价，不用注册资本替代发行股数。

### 3.3. 研报资料更新与正文

已配置证券CSV且同资料根存在stock-analyst-ranking时，按固定证券文件读取线索，不搜索全盘。点击“检查资料更新”显式重读并保存索引检查快照及检查时间；首次没有旧快照时不宣称新增数。mtime、入库／抓取变动不等于新报告发布，也不表示正式研究更新。

主日期为原研报发布日期，保留日／月／未知精度。封面报告日、公开分发索引日、实际取得、提取和暂存时间分别记录；API零点可能是日期占位，不假定真实发布分钟。日期有差异时列来源和待核说明，不能拿下载日统一替代。

本地索引没有URL或正文；未取得时仅为“线索／正文待取得”，不凭标题生成内容概述、机构观点或盈利预测。用户明确选取公开PDF后才有限请求，每份10MiB、35秒，并核公开来源、格式和身份。访问受限、失败、无文本层或身份待核分别提示，不绕限、登录或批量取数。

已取得PDF可通过已有PyMuPDF提取文本；缺依赖仍保留原件并标待提取，不自动安装。文本层成功不等于全表正确。只有实际正文、页码及已核注释支持的观点／预测进入补充区；保留财年、单位、归母／合并、每股口径和版本，源内笔误或股数歧义保持待核。预测不是承诺或已兑现业绩，研报原PE不是当前估值。

正文取得后先放私有根_workspace/platform/broker-cache，属于**暂存补充资料**。打开、提取或检查索引不会自动正式导入，也不替代最新基本面研究。S2的source-only暂存边界是此前阶段的行为记录；S3新增单独的“正式归档为补充资料”操作。

正式归档只在服务已核验本机相关宿主均能区分正式研究与补充来源时开放；能力未知或旧工具不兼容时保持关闭，并在页面说明原因，不能靠前端过滤绕过门槛。用户从已核正文发起归档后，服务再次核对证券、来源与指纹，追加具有独立ID的补充来源成果，并登记PDF及提取附件；同一来源重复归档返回已有成果。原发布日期仍是日期标签，取得、提取和归档另列。

档案室将正式补充研报列为独立科目；它可提供观点与预测追踪依据，不能当成完整或增量基本面研究，也不自动改写估值和主结论。只有完成明确的新专业研究，才能在原有研究链上形成新的经营判断。正式登记原件进入对应成果的导出和完整快照范围；仅有工作区缓存仍不在该范围内。

### 3.4. 角色与研究草稿

完整研究、增量研究和更正才参与正式基本面／技术面选择；补充研报及资料适配独立保留，未知模式保持unknown。较晚取得、提取或导入不更新主结论。/api/fundamental、/api/technical为已有组件只读投影，不是模型或取数任务。

档案室将原`broker_source`列为“补充研报”，按原发布日期筛选及排序；本次生成的`source_adaptation`列为“补充研究解读”，按研究日期，原研报日期查看父来源。解读不是新发布的券商原文，两类均不直接替代正式主研究。

准备研究时选择基本面／技术面／联合范围、Codex或DeepSeek、资料截止日期、研究方式、本轮问题与允许资料范围。“保留本页草稿”仍只存本页，不调用来源，刷新后消失；“开始研究”才提交持久任务。任务冻结完整证券、日期、来源和范围，切股不改变后台任务对象。

研报驱动更新只能明确选择**已核原页且正式归档**的补充研报；工作区暂存、线索标题和日期不明的来源不能直接送入研究。尚未归档时，先回基本面页核对并正式归档。资料作为研究输入与观点被采纳是两件事；页面“已供本次研究参考”只表示材料已供已完成的研究参考，附完成日及关联成果，不宣称全部观点已采纳或正式基本面已更新。

### 3.5. 持续跟踪与判断验证

日常先在研究工作台查看需要补证的公司，再进入个股“判断验证”。本页遍历同一完整证券身份的**历次成果和追加回顾**，不只看最近一份报告；最新成果没有新关注项，也不会清空旧项。首页、个股总览和下一步队列来自同一连续研究投影。

每项固定呈现：原判断与实际冻结日、原判据及观察窗口、后来证据及覆盖、检查状态与原因、下一步。来源成果、原文定位、研究截止、资料截止和生成日期各自保留。原始未结项和正式回顾原文仍可展开，时间轴可回到历次研究。模块、状态和关键词筛选只改变展示，切股重新确认当前证券的记录。

| 状态／视角 | 阅读方式 |
|---|---|
| 待验证／尚未到期 | 保留原条件；尚未结束的观察窗口不算失败 |
| 证据不足 | 缺规则、日期或同口径事实，列下一项需补证据 |
| 口径不可比 | 单位、财务期、价格基础或事实冲突需先核清，不计算改善幅度 |
| 待确认候选 | 只有原档明示结构化规则及同口径事实完备时才检查；候选不自动改成正式回顾 |
| 有正式回顾记录 | 可以回到原回顾日期、状态、证据ID和原原因；有回顾不等于原项已经关闭 |
| 历史观察 | 观察或回溯研究仍有跟踪价值，但不冒充事前数值预测 |

原自然语言中没有明确阈值，不从后来涨跌倒推规则；事后适配单独标注，不能把冻结日倒填。原报告没有结构化原因分类时，显示原原因和“未分类”，不擅自推断经营、时机或执行归因。不默认给总体命中率，不推断用户采纳、成交、盈亏或同日盘中先后。

“准备本项延续研究”将原项ID、判据、冻结日和缺口带入未执行草稿。“追加人工回顾”则是明确的本地归档操作，填写理由后才提交；首版只提供以下四项，避免在缺少合格证据时认定预测成功或失败。

| 人工操作 | 保存含义 |
|---|---|
| 保留原状态，记录新说明 | 保留原有效状态，追加本次观察或补证说明，不悄悄关闭旧项 |
| 观察窗口尚未结束 | 追加尚未到期的回顾，原窗口和定义保留 |
| 现有证据仍无法判断 | 明确记录证据不足及缺口，不将未知当0或失败 |
| 撤回本项，保留原记录 | 明确撤回并说明原因；旧研究及原定义仍可追溯 |

回顾提交绑定所读版本。若档案已发生变化，服务拒绝过期提交，页面重读并要求重新核对，不重放旧请求。该操作只追加有日期的回顾，不改旧文件、不形成新基本面或技术面主结论。需要形成新专业研究时，使用以下S4任务流程；两种操作的日期与记录分别保留。

### 3.6. 发起完整、延续或研报驱动研究

1. 顶部选股并核完整身份；在个股页选择“准备更新研究”，或从原关注项选择“准备本项延续研究”。
2. 选择范围、资料截止、本轮问题和来源。研报驱动从已正式归档的来源选择；材料范围和原发布日期在提交前核对。
3. 点击“开始研究”。任务页显示所选公司的实际阶段、创建／更新时间与后续问题，隐藏普通聊天、思考过程、命令和线程内部标识，不用虚构百分比代替进度。
4. 需要补充时，在该任务的问题卡中回答，再点“提交补充并继续”。回答绑定原任务和原问题；页面已过期时先重读，不把旧回答套入新问题。用户补充不是自动核实的财务事实。
5. 完成后由平台核身份、日期、组件及原件，再追加归档。可从任务打开本次成果；同证券看板重读新成果，另一证券的任务完成不会把其数据画到当前股票。

| 方式 | 用途与完成边界 |
|---|---|
| 完整研究 | 按相应专业框架组织报告，复用合格计算和图表；是报告范围，不代表重新取到全网最新数据。没有可信量化材料时必须保留问题卡，不能凭常识填数或冒称完整首研 |
| 延续／指定问题更新 | 承接原报告及跨历史关注项，保留原判据、冻结日、原资料截止和父成果；先说明本轮问题、新证据及仍缺什么，再形成限定结果 |
| 研报驱动更新 | 券商观点与预测只作补充；没有可核实的一手实质事件时归档为补充适配，不替代正式基本面主结论。后续正式增量须另核一手事实和明确内容角色 |

没有新数据时，旧财务、价格、估值和技术计算保持原截止；本次报告真实生成日另列。继承图表不是重新计算，沿用同一披露不能算新增季度或独立来源。需要从已配置本地数据重新计算时，先使用下述“检查本地数据”流程；专业研究任务不会暗中代替它取数或重算。无档证券可以创建正确任务并提出缺口，但缺量化材料时会等待补充，不以空白或虚构图表“完成”。需要新资料时先通过合格资料／专业研究流程形成可信输入，不把任意文本路径或回答直接变成已验证数据。

### 3.7. 重复提交、取消与恢复

任务页与顶部当前选股独立：可查看不同证券的任务，再进入对应公司研究。页面内输入草稿不是任务；关闭浏览器也不等于取消已提交任务。

| 状态／操作 | 含义 |
|---|---|
| 重复点击或提交结果暂未确认 | 保留同一请求身份，原样重试先寻找已有任务，不因为网络断开就认定未受理或另建任务 |
| 等待补充 | 只回答当前任务的待答问题；提交后在同一来源与证券下继续，不切换模型或改原范围 |
| 取消后续执行 | 停止后续步骤，旧档和已归档部分保留；取消不能撤销已发生的服务消耗 |
| 已中断／暂未完成 | 原任务、冻结输入与已有产物保留；重开服务不自动再跑付费研究，由用户明确恢复 |
| 恢复此研究任务 | 先核原会话／原turn与已有结果，再继续所需步骤；已有完整输出优先用于校验归档，部分保存只补缺部分，不覆盖旧记录 |
| 正在校验归档 | 已进入归档提交的部分不可取消；正常停机等待提交结束，不强杀进程或删除锁 |
| 已完成 | 结果只读；要改变范围、截止或来源时新建任务和新成果，不用恢复覆盖旧版 |

取消、恢复和回答绑定所读修订版本；状态变化后先重读。恢复不保证零消耗：后续新turn可能使用来源额度，平台没有可核费用时保持未知，不显示为免费，也无法退回已经消耗的额度。一次研究的完成、报告字节完整、金融判断质量和投资效果分别看待。

### 3.8. 执行权限、资料与会话边界

本版采用“平台托管资料与归档，模型负责受限解释”的分工。平台读取已核的正式档案／补充原件、继承有日期与指纹的数值和图表、核验结构并调用原归档工具；模型不直接改正式根、补写原manifest或运行任意CLI命令。网页不暴露完整对话，也不把密钥、会话库或原生HOME复制到任务材料。

执行准入要求：每个任务在进程内使用独立命名权限配置，只允许读取当次任务资料，拒绝文件写入；禁用模型的命令、浏览器、MCP、子代理等工具，并核对实际生效设置。配置或实际条件无法确认时不开始，不能只靠提示词声称隔离。**该约束的实际Windows权限与双来源、恢复分支是否通过，以本轮验证记录为准；说明书本身不构成已通过证据。**

两来源使用独立持久会话，并核同一已确认专属项目的后台身份及工作目录；仅工作目录相同不算项目绑定。继续原Codex HOME与现有认证，不修改全局模型配置。每次恢复重新核原来源、项目、证券、截止和当次任务资料范围，不能借恢复扩大权限。

### 3.9. 横向比较

1. 进入“横向比较”，将当前证券或“已有可信证券”加入比较池，选择2—5只。需要新对象时，先在顶部检索并确认完整身份再加入；比较池独立于顶部选股，不更改关注名单。比较池及条件仅保留当前页面，重载后重新选择。
2. 设置“资料观察截止日”，再选累计、单季或全年。默认采用所有证券都有的最新财报期，也可从共同期间选择；没有共同期间或缺资料就说明缺口，不用不同财报期凑齐。
3. 点击“读取同口径比较”。只读原档，没有模型／Wind／行情消费，不自动形成新报告或回顾。修改对象、日期或口径后，旧结果立即清除，再明确读取；切换顶部股票不会改变比较池。
4. 先看分项结论和经营／现金图，再看四区指标。金额经已核单位统一为元、页面显示亿元；比率以小数计算、页面显示百分比。现金转化用同期合并净利润作分母，归母利润单列；单季、累计、年度及期末余额分别说明。同比核本期和上年同期间的公开日期、来源及冲突，负或零基期不计算误导性比例。
5. 展开某指标的“核对依据与原报告”，查看附件、字段、指纹和研究／生成日期，再打开该证券的依据报告；不依顶部当前股猜报告归属。单位不明、数值冲突或缺数不画成零，不给强制排名。

资料观察日是**当时平台可见的研究截止**，不是统一的行情日。每股另列财报所属期、来源版本公开日期、研究和生成日期、行情末端及原技术计算口径。历史底表可能是后来比较版本，来源版本日期不等于首次披露日；不能把后来生成的研究拿到更早观察日使用。新解释不刷新旧数据、判断有效期或执行资格。

共同价格图仅接入可核的同币种**名义原价**。原技术分析使用参考链时，只有同份正式成果已登记原价快照、定义及分析输入血缘可核，才使用原价附件；不能直接将raw与qfq曲线归一100后混图。20／60／120／252个共同观察间隔分别要求N+1个共同价格点，始末日期明示；没有足够点数不冒充完整窗口。

图的“仅供诊断”表示：统一了名义价格和日期，**尚未消除全部权息、拆股、交易日历及缺数影响**，不是含分红总收益或可交易回报排名。旧技术指标仍按各自原计算口径，只并列文字状态，不比较不同价链的SMA／MACD等高低。绝对股价高低不代表便宜或昂贵。

PE保留各股原计算值、估值行情日、最新财务期与股本范围；A股价等值A+H股本与单A市值不能直接排名，历史情景期限及假设不同也不能比较目标空间。数值口径对齐不等于产品结构、经营阶段或会计估计完全相同；本版给分项事实与下一核验依据，不给综合分或投资潜力总排名。

比较只生成可重建视图。一次请求复用一份已校验的档案索引，每个实际附件仍核登记指纹；下次点击重新扫描，不用共享或跨请求缓存遮蔽新成果及损坏。正式档案恢复后可重新读取比较；浏览器偏好、任务工作区不在正式档案快照中，本版不增加页面备份或自由布局按钮。

### 3.10. 重开上下文、档案搜索和回顾边界

同一浏览器、同一运行地址下，重新打开可恢复已核证券、页面／科目、图表周期、指标、均线、显示根数，以及比较池和比较条件；恢复后重新读取可信档案，比较结果须再点击读取。不保存报告、凭据、研究草稿或问题回答，也不自动提交研究。只有仍在可信证券列表中的完整身份可恢复；未知身份和不合法条件忽略。浏览器拒绝存储时仍可正常使用。**服务重启可能更换端口，偏好不能保证跨端口恢复**；清除浏览器资料也会丢失偏好，正式研究不受影响。

档案室先选股票，再组合研究类型、研究／原发布日期范围和关键词。空格分开的词需同时匹配已登记名称、代码、标题、概述、来源或ID；这是元数据搜索，不是报告或PDF全文检索。正式报告历史行的概述覆盖尚不完整，可用ID定位并阅读原报告。原研报仍按原发布日期，补充研究解读按研究日期；搜索不改研究角色或主结论。

单独研究基本面或技术面时，可引用同证券、同观察截止可见的另一模块正式成果。报告保留对方ID、原生成／研究／资料截止及资格；失效成果仅作历史对照，不能当作当前依据或通过引用续期。辅助参考不扩大本次产出模块，也不把对方旧项、数值附件当成本模块新增证据。

每模块一次回顾最多50个选定旧项；默认待回顾项超限时，在创建任务和调用模型前给出分批提示。可从判断验证的原项卡“准备本项延续研究”，未选旧项保持；页面尚无任意批量选择器。旧任务恢复也核此限制。人工保守回顾不会把历史项恢复为当前可用，也不延长原窗口；流程状态不等于交易资格。

### 3.11. 检查本地数据、明确重算与恢复

1. 选定并核对证券，在个股页点击“检查本地数据”。平台只读固定来源，核对完整身份、字段和文件稳定性，冻结原文件字节、解析后的财务／日线／日历及各自指纹；此时尚未重算或调用模型。
2. 核对预览中的财务所属期、可见版本数、日线末端／根数、周期核对范围和限制。版本数是本地可见行版本数，不等于新披露次数。实际读取时间另存，较晚修订不能倒填为早年已知；财务日期只有日粒度时按当日结束保守判断可得。
3. 明确点击“重算并保存新快照”。服务重新核验配置、算法与冻结材料，且核对源文件从预览后未变化；变化时须重新检查，不从新旧文件拼一份结果。计算使用冻结日线，财务累计数与同年单季差分分列，缺失不补零，单位／版本限制原样保留。
4. 页面显示实际进度与已保存成果。财务形成独立专项简报、底表和计算；技术形成日／周／月／半年／年五周期计算及图表，两者各有新ID和日期，追加归档，不覆盖原报告。没有新披露时明确是同一财务期的版本核对与重算；新行情末端也不自动让旧公司观点和关注项续期或关闭。
5. 成功归档的本证券看板重新读取成果。切股仅切换展示，不改变后台证券；比较池涉及该证券时清除旧比较，仍须明确重新读取同口径比较。可用且通过核验的固定沪深300来源随本轮冻结，只作同日期名义价格诊断背景；本流程不重新计算申万行业组合、不生成行业排名，缺基准不拿个股代替。

本地更新不使用Codex、DeepSeek或Wind，也不承担专业研究的取消、补充问题与会话管理。一次只执行一项本地重算；关闭页面不代表取消。其状态与恢复如下：

| 状态／情况 | 处理 |
|---|---|
| 范围已核对，等待确认 | 预览已经冻结；核对限制后明确开始，未确认不计算 |
| 等待／正在重算 | 只查询当前进展，重复提交同一更新不并行另建 |
| 部分成果已保存 | 展示已归档ID；修复原因后点“继续同一更新”，核验已有部分并只补缺项 |
| 更新未完成／重算已中断 | 保留冻结输入和旧档，重开不自动执行；明确继续前仍核源与算法，变化须重新预览 |
| 请求结果暂未确认 | 先读取同一证券状态，不因断网另建更新；页面提供状态核对，不盲目重放 |
| 新快照已保存 | 成果只读；证券、源SHA、算法／配置、实际依赖版本及本次可纳入的数据选择均相同时，再次检查返回同一更新及成果，不新增同输入档案 |

幂等身份还绑定稳定的“本次可纳入的行情末日、财务公开版本选择及指数末日”，不以每次取得时间不同就新建。即使文件字节未变，跨收盘或公开日后重新检查、可纳入的选择发生变化时，也会形成新预览；原快照保留原取得时间、截止和资格，不自动续期。

本地数值与专业判断分层：供应商原价、未独立认证的单位或复权仍保留原资格；2026窗口内的完成期核对不能升级为完整价格认证。经营现金流以同期合并净利润作分母，注册资本不作股数，未核股本不新算估值。新数值可以供后续明确的完整／延续研究引用，但不会自动认定旧判断成功或失败，也不会自动发起模型研究。

## 4. 原报告与日期

研究列表依原research_asof区分研究日期，generated_at为实际生成，data_asof表示实际覆盖；补充研报按原published_date标注和筛选，导入时间另列。未知保持未知，同日不同ID为独立版本；打开或下载不改写日期、旧判据或valid_until。新资料只能通过完成新专业研究并合法追加，才更新正式判断。

判断验证保留跨历史未结项，筛选不删旧项。已有回顾显示原原因；无反馈保持未知，不从触价推断成交／盈亏或预测命中。混合财务／行情／暂停分钟的回顾可保留data_asof=null。

报告阅读窗提供安全Markdown版，支持常用标题、表格、列表、链接等，不保证任意扩展排版。原Markdown不变，原HTML不在应用内执行；图片仅从本报告已明示且指纹一致的PNG读取。未归档本地路径和任意私有文件不自动补读。

JSON／PNG／HTML按原清单下载，研报PDF按已登记证券／source_id核指纹下载，均不接受任意路径。缺件、篡改、链接路径或元数据错误显示失败，不伪装无档，也不用重建catalog掩盖。

## 5. 跟踪名单

确认证券后“加入关注”保存完整身份，重复加入不重复；“移出关注”只移名单，不删成果、回顾、旧图或关注项，也不等于撤回判断或成交。新增研究不自动代表关注或持仓。

名单唯一位于私有根platform/watchlist.json，复用研究室同一写锁、临时文件和原子替换，不入catalog。写入冲突等待原任务，不删除锁或手工覆盖。名单的备份契约见[档案室说明书](../skills/stock-research-archive/references/档案室说明书.md#5-备份校验与恢复)。

## 6. 文件与备份

    ROOT/
    ├── securities/                 正式原研究、回顾、补充来源及登记附件
    ├── config.local.json           原根标识
    ├── catalog.json                原可重建索引
    ├── platform/watchlist.json      持久跟踪名单
    └── _workspace/
        ├── platform/               本机状态、协调锁与日志
        │   ├── broker-cache/       研报索引检查、PDF及提取暂存
        │   ├── tasks/              持久任务、冻结输入、尝试及恢复状态
        │   ├── local-data-updates/ 本地更新状态、源字节／日线冻结及计算工作文件
        │   ├── local-data-config.json 本地更新开关与技术Python绝对路径
        │   └── research-engine.json 本机引擎配置与凭据入口，不包含页面表单
        ├── views/                  阅读／导出副本
        ├── backups/                手动快照
        └── restore-tests/          新目录恢复演练

工作区不进入正式扫描与档案快照源；可能含临时认证、日志和研报正文，不上传或入源码。原报告不搬迁，浏览器／下载副本不当正式记录。

本仓库配套档案工具的完整快照纳入固定platform/watchlist.json，并兼容旧快照；以工具输出的快照版本和校验结果为准。正式补充来源中的登记PDF和提取附件随成果进入导出、完整快照及新目录恢复，恢复后仍须核对原件指纹和来源角色；不能只凭目录或catalog存在就认定恢复成功。旧全局档案室0.1.0不包含名单且不读快照/2；源码版本、全局安装和实际验证分别记录，不能把修改源码写成已安装。操作契约见[档案室说明](research-archive.md)。

快照和恢复只能写新目录，不覆盖正式根。快照不加密，同盘恢复演练不是异盘容灾。本版无自动备份／云同步／清理；页面也不提供未实现的备份按钮。手动备份、验证和新目录恢复由本机配套档案工具执行。内存草稿、尚未正式归档的研报暂存及_workspace中的任务／恢复状态不在这份档案快照内；本地更新的源冻结、工作文件、状态和配置同样排除。已成功正式归档的财务／技术新成果及登记附件进入**下一次明确创建的完整快照**，完成更新不会自动创建备份。模型原生会话仍在原HOME；正式研究中的来源和任务关联可随成果保留，但不能据此声称完整恢复了未完成任务或本地更新队列。

## 7. 停止、重开与故障处理

关闭页面不停止服务，再运行原入口会核对并打开同一实例。需要停止时传相同私有根和项目参数：

    python -X utf8 -B app/launch.py --root $archiveRoot --project-dir $projectDir --stop

启动器核对实例后发送认证停止请求，不按旧PID结束其他Python／Codex。平台停止后不接新任务，执行中的专业研究转入停止／待恢复；归档提交中则等待完成。本地数值更新使用独立流程，正常停止会等待当前计算／归档结束，不提供取消已保存部分的操作；异常中断后保留状态，须明确继续。停止不删档；操作系统启动锁随进程释放，不按年龄擅自删除任务锁。若直接前台运行python -m app.server，可在该窗口Ctrl+C停止。

| 现象 | 处理 |
|---|---|
| 提示从本机入口打开 | 再运行启动器，不复制裸端口或公开访问凭据 |
| 启动失败 | 核私有根、项目、Python和权限，私有server.log仅本机排查 |
| 仍是旧布局 | 正常停止旧服务、启动当前版本并重载，不删名单或档案 |
| 搜索无候选 | 核实际档案／名单／CSV身份，不联网猜造 |
| 切图后日期仍旧 | 归档末端不因重绘或索引检查刷新 |
| 本地更新入口未启用 | 核local-data-config.json三项配置、明确的技术Python及固定数据目录，不让页面自动找环境 |
| 预览后提示来源／算法变化 | 重新“检查本地数据”，核对新冻结范围后再明确重算，不删旧更新或旧成果 |
| 本地更新只保存了部分成果 | 阅读已归档部分，核资料和依赖后“继续同一更新”；已通过核验的同ID成果不重复归档 |
| 重算完成但公司观点日期未变 | 财务专项只更新数值；原公司观点保留原ID与日期，需要明确专业研究才能形成新观点 |
| 图有diagnostic或缺值 | 保留复权、日历、完整性和暖启动限制 |
| 研报封面日与公开索引不同 | 分别保留，按来源核日期，不用取得日替换 |
| 正文未取／提取失败 | 保留线索和原因，不生成观点或自动安装 |
| 正式归档入口未开放 | 核服务能力和实际宿主角色兼容；不把缓存改名或手工塞入catalog绕过门槛 |
| 暂存PDF不在档案备份 | 工作区明确排除；满足门槛并正式归档后，核对应成果附件清单 |
| 回顾提示档案已变化 | 重新读取原项及最新回顾，再填写新说明，不重复旧提交 |
| 旧项仍显示待验证 | 有回顾不等于已关闭；查看有效状态、证据覆盖和下一步 |
| 刷新后草稿消失 | 未提交草稿仅内存；已提交任务从任务页重读，不重新点击新建代替恢复 |
| 研究按钮不可用 | 核来源可用状态、原档读取与资料正式归档；未核条件不自动调用 |
| 任务等待补充 | 在原任务卡回答，不把答案当成已核数据；缺量化材料不能凭空完成 |
| 提交结果暂未确认 | 原请求重试或查询任务列表；不要因为连接失败创建第二份同范围任务 |
| 取消按钮暂不可用 | 可能已进入归档提交；等待结束，保存结果不会被撤销 |
| 恢复提示原状态待核 | 先核原turn和已有产物，不改来源、项目或原输入后强行重发 |

## 8. 接口与后续边界

| 接口 | 用途 |
|---|---|
| GET /api/fundamental | 本证券经营组件、指标、历史和来源 |
| GET /api/local-data | 仅传security_id，读取该证券更新是否可用及最新状态，不预览或重算 |
| POST /api/local-data-preview | 仅提交security_id，核固定本地源、版本及范围并冻结输入，尚不重算 |
| POST /api/local-data-run | 仅提交security_id与update_id，核预览身份后明确重算／继续同一更新；同输入幂等 |
| GET /api/comparison | 2—5个完整security_ids（逗号分隔）、asof日期、period_basis、可选financial_period及price_window；只读同口径比较 |
| GET /api/analyst-updates | 本地线索、日期、检查及暂存资料状态 |
| GET /api/analyst-source、/api/analyst-source-file | 按证券／source_id查详情或原件，核指纹，不读任意路径 |
| POST /api/analyst-refresh | 显式检查固定本地索引并记录检查时间 |
| POST /api/analyst-fetch | 显式有限取得允许公开来源的PDF，不形成专业研究 |
| POST /api/analyst-archive | 兼容能力门槛下显式正式归档已核补充资料，重复来源不重复导入 |
| GET /api/continuity | 跨历史原项、回顾、观察窗口、明示规则候选、证据覆盖、队列与时间轴 |
| POST /api/continuity-review | 绑定原项和所读版本，提交四类保守人工回顾；理由必填 |
| GET /api/research-tasks、/api/research-task | 跨证券任务列表、单任务状态、进展、问题与已有结果 |
| POST /api/research-start | 用户明确开始，冻结范围并以稳定请求身份防重复 |
| POST /api/research-answer | 绑定任务、问题及版本，提交补充并继续 |
| POST /api/research-cancel、/api/research-resume | 停止后续执行，或核原会话／产物后恢复同一任务 |

写请求沿会话、Origin和CSRF校验；证券、源ID、公开链接及文件指纹分别核对。失败不回退为前股图或虚构结论。

S1—S5已有的旧档研究闭环保留，本地受控更新作为P1补充；实际验收见[验证记录](validation.md)。D5整体仍为部分完成：无档通用首研、主动联网取得新财报／行情、完整价格与全历史交易日历认证、研究生成事前量化规则、事件／条件图层和行业相对交互，以及跨端口偏好和完整档案GUI仍需后续开发。本地更新现已能在明确范围内冻结与重算，不能把它扩称自动发现新财报、重新核验公告原件或完整公司研究。仍可按既有工具手动备份及新目录恢复。

Codex与DeepSeek的实际调用、项目关联、执行权限、取消／恢复、真实两股成果、全局安装和公开发布分别记录。当前源码或界面具备入口，不等于所有环境与分支已实测；具体通过及限制见[验证记录](validation.md)。
