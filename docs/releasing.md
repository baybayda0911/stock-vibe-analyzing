# 发布清单与分发核验

本仓库只分发研究工作流与维护文档。公司研究报告、金融原始数据、图表样本、模型运行记录、认证资料和本机管理资料不进入源码提交或 Release 附件。

## 明确的发布白名单

[release-files.txt](../release-files.txt) 逐文件列出拟公开内容。准备发布时人工审查清单及文件内容；只按清单暂存文件，不使用无范围的全量暂存。`.gitignore` 是辅助规则，不能代替实际提交树和归档内容核验。

维护脚本需要 Python 3.10+ 标准库，不是 skill 的运行依赖。在仓库根目录执行：

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 scripts/build_release.py --output '../release-artifacts/stock-vibe-analyzing-0.1.0'
```

输出目录必须位于仓库外，并且不能含已有同名附件。脚本生成集合源码 ZIP、基本面 skill 独立 ZIP 和 SHA256SUMS.txt。源码 ZIP 只含白名单文件；独立 skill ZIP 只含入口、MIT LICENSE、Codex 元数据及两份参考资料共五个文件。脚本会验证归档成员、实际字节及 ZIP 完整性。

测试会在临时目录植入虚构研究报告、金融 CSV、凭据文件和额外文档，确认均未进入归档；还验证危险清单路径、缺文件、许可证差异、仓库内输出和重复覆盖会被拒绝。测试资料均为虚构占位，不使用真实金融数据或凭据。

## 提交与发布

1. 按维护规则完成结构、安装隔离及实际相关行为验收，更新验证记录和 CHANGELOG。
2. 完成独立文件安全复查并交付脱敏报告；该阶段完全不执行 Git。
3. 进入已另行明确授权的 Git 发布阶段，核对目标身份、远程默认分支、历史和工作区，保留已有文件及本地资料。
4. 逐文件暂存白名单。实际提交树应与白名单完全一致；已有远程历史另行核验，不以当前树干净推断历史无敏感内容。
5. 提交后再次确认没有 reports、data 或其他清单外文件。标签 `v0.1.0` 指向经核验的仓库提交；不覆盖已有标签或强制推送。
6. 以正常推送发布，并上传两个 ZIP 和 SHA256SUMS.txt。下载远程附件核对哈希与成员；自动生成的源码归档也核对成员。

Release 说明列出所含 skill、自身版本、安装方法、MIT 许可、已执行测试及限制。季度业绩与定价图表的新板块尚为仓库外评审样本，未经采纳不计入本次功能。
