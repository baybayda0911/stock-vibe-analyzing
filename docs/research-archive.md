# 股票研究档案室

stock-research-archive 0.3.0配合研究室0.3.0复用同一私有根，提供个股首页／时间线、元数据筛选、版本对比、补充来源与注册原件导出，以及包含可选平台跟踪名单的完整文件快照恢复。操作协议及时间边界唯一维护于包内[档案室说明书](../skills/stock-research-archive/references/档案室说明书.md)。

## 职责

基本面与技术面形成专业研究；研究室回顾原判断、原因及用户反馈；档案室负责保存、定位、比较和恢复。持久层继续是一套源记录与一个派生catalog。纯查档不取行情或重跑股票分析，文件变化不直接视为观点变化。

## 使用

独立复制[档案室Skill](../skills/stock-research-archive/SKILL.md)的七个资源即可，运行只用Python 3.10+标准库。宿主必须明确提供既有research_lab.py工具的绝对位置及已确认的私有根；各包没有相邻Skill硬引用。工具缺失就说明未执行，不自动安装。

可以说“查看这只股票历次研究和未结项”“比较这两个版本”“导出这份报告的已归档资料”“备份私有研究档案并恢复到新目录核对”。首页输出离线HTML／Markdown／JSON，生成页面时间不刷新原报告资格。命令、过滤含义、失败状态与备份范围见说明书。

私有根内使用_workspace/views、_workspace/backups、_workspace/restore-tests；原securities和历史ID保持，不搬迁。工作区排除在正式记录扫描和备份源之外。快照包含全部源文件，catalog在恢复时重建；只接受新输出目录，原档不覆盖。

仓库[工作台S3](platform.md)提供查档、原件阅读、跟踪及追加回顾，版本比较／导出／备份／恢复仍用档案室工具。档案室0.3.0配研究室0.3.0共享角色，正式研究与补充事件分开。合法source_ref的补充资料导出同时带注册原PDF及import.json；损坏引用拒绝，旧无引用列原件缺口。原imports及名单随快照/2进入校验和新目录恢复，兼容旧/1；暂存、任务、日志与凭据排除。旧工具能力不同，实际安装与宿主加载情况见验证文档。

正式研究及补充来源使用`stock-research-role-resolver/1`识别；研报按原发布日期标注，取得或归档较晚不替换正式基本面。平台只有在明确配置的Codex与Trae两处安装、共同角色能力及各34资源指纹均通过时才开放正式补充归档，变化或未知则关闭。仅保存原件但适配未完成标为partial，可按原ID重试，不能当完整补充成果；原件登记也不等于已经执行并验证备份。

当前仓库0.12.0／基本面0.3.2／研究室0.3.0／技术面0.4.2／档案室0.3.0，两端全局技能已各备份后更新并核验34资源。该文件核验限明确安装位置，不保证所有宿主或未来版本兼容；Trae本轮没有重做对话验证，也不保证现开客户端热加载。安装与验证边界统一见[验证记录](validation.md)。

## 限制与验证

只按已存元数据／旧项文本筛选，不做全文或任意附件解析。资料包只含明确归档附件，未列原件及外部链接说明缺口。文件夹快照不加密，同盘副本不构成异盘容灾；校验不等于可信时间戳或作者认证。

当前尚不接情绪面存储类型、账户、云上传、后台备份或自动收益计算。测试与中际旭创内测只说明对应功能和数据覆盖，不构成新投资判断或宿主自动触发保证。实际结果见[验证记录](validation.md)；发布只按[白名单流程](releasing.md)，不包含真实报告、页面、快照或恢复副本。
