# 验证方法与记录

## 每次需要检查的事项

- 逐个检查变更涉及的 `skills/<name>/SKILL.md`：YAML 可解析，`name` 与目录一致，`metadata.version` 有效，触发描述能与相邻 skill 区分。
- 检查相应的 `agents/openai.yaml`：展示名和示例调用名称正确，自动选择策略与预期一致。
- 每个 skill 单独复制后，入口及其依赖的所有相对引用仍在安装目录内可读；不能靠完整仓库掩盖资源缺失。
- 仓库 Markdown 相对文件链接有效；根 VERSION 对应 README 和 CHANGELOG 的仓库版本，各 skill 版本对应清单。原提示词 V3.0 不参与版本一致性判断。
- 在隔离目录运行 README 的复制安装步骤，比较源与副本；目标存在时应停止，不覆盖旧文件。新增 skill 应分别验证。
- 如有 skill-creator，执行其 `scripts/quick_validate.py`。该工具需要 Python 与 PyYAML，是可选维护工具，不是基本面 skill 的运行依赖。

官方结构校验的通用命令形式（替换本机实际 skill-creator 位置，从仓库根目录执行）：

```powershell
python -X utf8 '<skill-creator目录>/scripts/quick_validate.py' 'skills/stock-fundamental-analysis'
```

结构检查不能证明自动选择和实际金融研究质量。安装后按下表做行为验收，记录宿主、版本、日期、是否实际读取目标 skill、所用资料及结果。

依 skill-creator 的独立前向验收流程，评估者只获得实际用户请求、安装 skill 和离线摘录，未获得标准答案或疑似缺陷。四个输入顺序执行、共用同一评估上下文，实际回答及计算记录只保存在仓库外。

| 输入 | 实际观察 |
|---|---|
| 首次离线基本面研究，限制篇幅 | 实际读取入口及两份完整研究依据；按摘录交付压缩的初步报告，复算合并毛利率，保留供应商数字差异和分部口径区别，不编造现价或完整财务历史 |
| 历史截止日研究 | 按发布日期排除截止日之后的季度和半年报摘录；没有拿后来业绩证明当时观点，没有编造截止日前缺失的资料 |
| 未指定 A/H 股的当前每股估值 | 先请求必要的证券类别及对应报价，不直接给未经核验的现价、每股目标价或贵贱判断，也未索取持仓 |
