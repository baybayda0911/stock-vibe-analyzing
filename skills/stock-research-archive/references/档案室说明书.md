# 档案室说明书

适用stock-research-archive 0.2.0。仅Python 3.10+标准库；不安装依赖、不联网、不运行Git、不接交易账户。归档仍沿已有研究室协议，档案室没有第二套数据库。

## 1. 安装与定位工具

独立包包含入口、MIT、Codex元数据、本说明和三个脚本共七资源。单独复制即可；仍需要宿主明确配置一个支持stock-research-lab/1协议的research_lab.py工具。它可以来自任意已核验安装位置，不硬引用兄弟目录。

根从用户指定、STOCK_RESEARCH_LAB_ROOT或项目本机配置archive_root取得，工具位置由用户／可信工具清单／本机配置取得。CLI始终显式传根与--lab-tool；不自动发现、扫描全盘、更新全局工具或复制私有配置进安装包。只有--help不需要已配置工具。

以下ROOT、TOOL、ASOF和OUT均为明确绝对路径／带时区截止；原始研究根必须已初始化、Git范围外、路径无链接。ASOF用于决定当时允许读取哪些成果，不用生成页面时间刷新旧证据。

```text
python -X utf8 -B scripts/research_archive.py view ROOT --lab-tool TOOL --security SECURITY_ID --asof ASOF --output-dir OUT
python -X utf8 -B scripts/research_archive.py compare ROOT --lab-tool TOOL --security SECURITY_ID --asof ASOF --left RESULT_A --right RESULT_B --output-dir OUT
python -X utf8 -B scripts/research_archive.py export ROOT --lab-tool TOOL --security SECURITY_ID --asof ASOF --result-id RESULT_ID --output-dir OUT
python -X utf8 -B scripts/research_archive.py backup ROOT --lab-tool TOOL --output-dir SNAPSHOT
python -X utf8 -B scripts/research_archive.py verify SNAPSHOT --lab-tool TOOL
python -X utf8 -B scripts/research_archive.py restore SNAPSHOT --lab-tool TOOL --output-dir NEW_ROOT
```

退出0表示操作完成；错误JSON写stderr并退出2。不得只凭输出目录存在判断完成，检查命令退出与返回状态。已有输出不覆盖。

## 2. 个股首页与时间线

view输出report.html、report.md及archive-view.json。首页提供可见成果、研究日期时间线、全部跨历史未结项、父链及回顾／计划／反馈的已存元数据。HTML离线生成，无CDN、自动取数或后台服务；原件链接仍指向同一私有根。比较与查阅页面不是新的专业研究成果，不自动登记为新基本面／技术面报告。

--module可选fundamental或technical；--date-from和--date-to按研究截止的日期做含首尾筛选；--query检索已核元数据与旧项文本，不是全文搜索或附件解析。没有日期筛选时，未知研究日期单列；有日期筛选时排除未知项并说明。页面明确过滤范围，跨历史未结项、计划与成交不随成果筛选被隐藏。

generated_at、research_asof、data_asof分别展示，不把晚生成或导入视为新研究。当前引用资格由原工具逐项给出，false可能来自历史用途、需复核、来源时刻未知、无冻结项或期限；不一概称过期。档案室不会主动获知新财报、拆股或市场事件，仍须专业研究核验。

使用支持stock-research-role-resolver/1的研究室工具时，查档页另列最近正式基本面／技术面研究及补充来源事件。完整、增量及更正研究才参与正式研究选择；broker_source、source_adaptation按其公开日期呈现，较晚取得或导入不替换正式主结论。全部历史和未结项仍保留。旧工具没有统一角色识别时明确标为“角色待核”，不按文件名、较晚导入日或模块名猜测正式报告。

普通对话可以说“查看这只股票历次研究和未结项”“按研究日期查技术报告”“比较两版研究”。没有唯一证券时先核身份；普通查档不索取持仓。

## 3. 版本对比与资料包

compare的两个ID必须属于同证券／股类／币种，且在ASOF可见。对照元数据、父版本、原冻结项／后来追加状态、报告及附件指纹。异模块可并列，但不是同一研究方向的评分；字节变化不等于新结论，也不自动计算财务或价格差、预测命中、收益。

export输出report.md、manifest.json、items.json与原已列附件，再生成archive-package.json记录实际文件、摘要、原日期及导出时间。仅所选成果，不自动沿父链复制全库；父版本仍在原根。缺失本地链接与外部本地依赖分别列出；不跟随链接寻找或下载原件。只有已归档并复制的资源才声称随包保存。当前主报告链接检查范围为report.md、report.html及details.html，不代替任意脚本／CSS依赖分析。

已正式导入的补充研报通过research-components.json顶层source_ref显式关联原件：恰含security_id、import_id、original_sha256三项，不接受文件路径。导出从同证券、同成果的注册import.json解析原件，复核导入时间、原日期依据、指纹及普通文件要求，再复制到original-sources/IMPORT_ID/original/原文件名，旁存注册import.json。archive-package.json的source_originals记录原件相对路径、公开日期及精度、导入／取得／提取日期和指纹引用；发布日期只有日期时不补造时刻。此功能须由兼容统一角色识别的研究室工具校验补充来源角色，旧工具会拒绝带source_ref的导出。

source_ref指向其他证券、其他成果、未注册或未来才导入的资料、指纹不符或路径异常时，整个资料包不发布。原件不能凭报告超链接、原source_path、文件修改时间或文件名猜取。没有source_ref的普通旧报告仍按原范围导出，不声称附有研报原件；若统一角色已识别其为补充来源，包内source_original_gaps明确列出missing_registered_source_ref，不能把适配报告当作原件保存成功。

导出日期不刷新原报告有效性。资料包是私有阅读副本，不允许作为公开项目发布附件。

## 4. 一个根目录内的工作区

推荐沿用已确认的私有根，新增：

```text
ROOT/
├── securities/                  原源记录及版本，继续由既有工具维护
├── config.local.json            原根标识
├── catalog.json                 可重建派生索引
├── platform/watchlist.json      可选跟踪名单，不写入catalog
└── _workspace/
    ├── views/                   查阅、对比及资料包，每次新目录
    ├── backups/                 手动快照，每次新目录
    └── restore-tests/           恢复演练，必须新目录
```

工作区不纳入正式记录扫描及快照源。view／compare／export在根内只允许_workspace/views之下；backup在根内只允许_workspace/backups之下的新目录。恢复拒原根与已存在目录、快照自身／其子目录和任何已初始化研究根的securities子树。也可以显式选其他Git外私有新目录；工具不迁移原根。

## 5. 备份、校验与恢复

backup读取README.md、config.local.json和securities全部普通文件；存在固定platform/watchlist.json时也纳入，形成snapshot.json及payload/。名单可缺失，不因此要求迁移旧根；名单必须为无链接的普通文件，包含且仅包含schema_version="stock-research-watchlist/1"、带时区ISO updated_at和securities数组。每个证券恰含研究室完整身份七字段security_id、company、market、exchange、code、share_class、currency，security_id符合market-exchange-code且不能重复。名单保留原字节，恢复不把名单证券或名单更新时间写入研究catalog。

正式研报原件及注册日期位于securities/证券/imports/，连同适配成果和research-components.json明示附件自动纳入上述整棵源记录快照，无需改变/2快照协议。恢复后由原注册身份与指纹继续定位原件，保留原PDF字节和日期，不回写旧成果。尚在_workspace研报缓存的资料属于临时资料，不能冒称已正式归档或已进入备份；须先完成正式导入再备份。

只允许上述固定名单路径；其他platform文件、_workspace内任务与凭据、派生catalog、写锁、_staging和_workspace排除；空目录不是研究内容。源根先通过原工具校验，取得同一lab.writer协作写锁，在复制前后复核源文件集合和全文件SHA256／大小，复制完成后再发布快照。平台名单写入也须使用同一写锁；名单新增、删除或字节在复制期间变化会使备份失败。失败不留下完成状态的半包。

新snapshot.json使用stock-research-archive/2协议：schema_version、kind、created_at、lab_schema_version及files；每个文件只有path、size_bytes、sha256。/2仅新增可选platform/watchlist.json范围，原研究室stock-research-lab/1协议不变。verify／restore同时接受无名单的旧stock-research-archive/1；旧/1清单仍禁止platform路径。旧版档案室工具不能验证或恢复/2快照，须使用本版或兼容新版；旧快照无需改写。

清单相对路径、重复／大小写冲突、危险名称、遍历、链接、多余或缺失文件都受检查；verify逐项复算，验证名单契约并核原研究协议。未列文件、其他platform路径及名单目录均被拒绝，不能借清单夹带任意平台文件。快照清单自身不提供外部签名或可信时间戳，不能证明原作者或事前可得。

restore先完整验证快照，复制原字节到新的私有目录，建立空_staging并用既有工具重建catalog。源记录、原生成与截止不改写；catalog的重建时间可以变化。全部源文件再核一致后发布新根；不在原根覆盖恢复。恢复演练的后续写入留在副本，不能把测试review当真实研究或回写正式档案。

现有底座只对研究报告／冻结项／明示附件等提供内建指纹复验，快照层会覆盖所有纳入的源文件，包括回顾、计划、反馈和导入原件。索引重建不能恢复已丢失原件。备份是手动文件夹副本，不加密；同盘恢复演练不具备硬盘故障容灾，跨盘方案另行明确。

## 6. 与研究室及专业模块衔接

档案室回答“在哪里、哪一版、怎样取回”，研究室回答“原判断后来怎样”；基本面和技术面产生新证据与结论。用原工具追加新研究／review，仍保持同一私有根与稳定item_id。查阅与导出不调用行情、不新增预测、不重跑全部模块。

未来情绪模块尚不在原底座允许的专业模块中，不能绕过原校验写成已支持。独立安装仅保证本包资源自包含；外部档案工具缺失则说明未执行，不以相邻目录假设替代配置。
