# 研究室工作流与工具协议

## 目录与时间

私有根由用户配置，必须在Git仓库外。`init`建立README、config.local.json、catalog.json、securities和_staging；证券／日期子目录在实际归档时创建，不造空股票报告。研究按证券／fundamental或technical／研究日期／result_id保存；review按回顾日，plan按稳定ID及版本，execution按成交月份及导入ID，import保留指定原件与适配关系。

当前适用和历史可回顾分开。`generated_at`是真实生成时间，`research_asof`是信息截止，`data_asof`是数据覆盖；`public_at`是原证据公开时间，`frozen_at`是本记录冻结时间，`valid_until`和`review_due_at`是有效／复核条件。时间带时区，财报所属期另存。导入日不替代原日期，只有日期的来源不要伪造精确时分；时点资格不足就标待核。

已知时刻使用带时区ISO；资料没有精确数据截止时`data_asof`可为null，公开时刻不明时`public_at`可为null并保留`public_at_precision`／原日期说明。未知不得用报告期末、生成日或公开时刻补造，也不能获得自动当前引用资格；原件和定性回顾仍可保存。

工具按字段校验，不会自动得知新财报、拆股或市场事件。宿主取得本次新证据后逐项复核并追加review；打开旧文件、重建索引、更新mtime都不刷新资格。默认关注项待复核；显式给予当前引用资格也需证据与期限，过期后仍可历史回顾。

## 命令

所有命令从本Skill的`scripts/research_lab.py`执行，Python 3.10+标准库。位置和根用参数传入，不依赖仓库根或相邻Skill。

```text
python -X utf8 -B scripts/research_lab.py init ROOT
python -X utf8 -B scripts/research_lab.py context ROOT --security SECURITY_ID --asof ISO_WITH_TIMEZONE
python -X utf8 -B scripts/research_lab.py list ROOT --security SECURITY_ID --asof ISO_WITH_TIMEZONE --module fundamental
python -X utf8 -B scripts/research_lab.py archive ROOT --request-json REQUEST.json
python -X utf8 -B scripts/research_lab.py review ROOT --request-json REQUEST.json
python -X utf8 -B scripts/research_lab.py import ROOT --request-json REQUEST.json
python -X utf8 -B scripts/research_lab.py plan ROOT --request-json REQUEST.json
python -X utf8 -B scripts/research_lab.py execution ROOT --request-json REQUEST.json
python -X utf8 -B scripts/research_lab.py reindex ROOT
```

`ROOT`等为说明性参数，换成已配置的真实值；不要照字面建立ROOT目录。写入请求使用唯一UTF-8 JSON文件，放私有根允许的临时工作位置；正文及用户原件通过绝对路径传入。不要在命令里拼接敏感正文。用模块docstring和`--help`核对精确请求字段；报错后修正具体字段，不换较宽松的保存方式。

旧档导入若返回`partial:true`且原件已保存、成果未完成，保留原件及登记，按原import_id／result_id和相同原始元数据重试完成；不要改ID绕过或删除已保存原件。工具核原件指纹和重试元数据；完整导入后的重复请求仍拒绝。

成功返回JSON；检查`saved`与`catalog_updated`等实际字段。内容已保存但索引失败时保留结果，再用`reindex`恢复，不能重复生成同ID覆盖。命令报错保留原件，并说明受影响范围。

## 归档与冻结项

`archive`包含：security对象（security_id、company、market、exchange、code、share_class、currency），module（fundamental或technical）、module_version、result_id、generated_at、research_asof、data_asof、parent_result_ids、report_file、evidence和items。security_id及各ID用安全字母、数字、连字符、下划线；不要把路径当ID。

evidence记录`evidence_id`、`source`及`public_at`；关键数值另在报告／计算文件保留可追溯输入。items保留稳定item_id、type、text、report_locator、evidence_ids、frozen_at、status及definition，原定义不覆盖。支持类型及冻结内容：

| type | definition所需内容 |
|---|---|
| prediction | metric、expected、unit、period、deadline、baseline、tolerance、evaluation_rule |
| hypothesis | proposition、mechanism、support_condition、falsification_condition、check_window |
| management_commitment | quote、source_public_at、metric、period、revision_context |
| observation | what、why、next_evidence |
| technical_scenario | timeframe、inputs、trigger、confirmation、invalidation、observation_window |

字符串字段写清实际判据；没有事前方向和规则的项使用observation，不临时编造一个“预测”。当前用途用current_use表达eligible、needs_review或historical；eligible需说明理由、有效期限及可核实证据。日历期限不替代新事件复核，已触发失效则追加失效记录。

`context`扫描原始记录而非只信catalog，返回results、excluded_results、跨历史pending_items、plans及executions。结果中仅部分item合格不代表全报告都可作为当前依据；读逐项理由和原文再引用。同一来源经多个报告传递不增加独立证据。

## 明示附件与可恢复归档

`archive`和`import`可选`attachments`；缺省或空数组保持原有请求兼容。附件每项严格只有三个字段，例如：

```json
"attachments": [
  {"source_file":"/ABSOLUTE/analysis.json", "relative_path":"analysis.json", "media_type":"application/json"},
  {"source_file":"/ABSOLUTE/chart.png", "relative_path":"chart.png", "media_type":"image/png"},
  {"source_file":"/ABSOLUTE/chart.html", "relative_path":"chart.html", "media_type":"text/html"}
]
```

以上是请求中的字段片段，使用时放入完整请求对象。源文件须为绝对路径的普通文件，不经链接／reparse路径且不在Git工作树内。相对路径是归档后相对`report.md`的位置，可用`charts/chart.png`等子目录；报告中的链接须与此一致。只接受JSON／PNG／HTML及对应媒体类型；不接受路径逃逸、绝对／反斜线路径、设备名、危险字符、大小写重复或重叠路径。`report.md`、`items.json`、`manifest.json`、`review.json`、`trades.json`、`import.json`等控制文件名及`vNNN.json`不能用作附件名。

工具复制明示文件，不整盘搜索、不跟随HTML外链、不执行HTML。JSON须为有效UTF-8且无NaN／Infinity；PNG检查文件签名，完整图像内容由生成方验收；HTML须为UTF-8。调用方应列全报告需要的本地资源，并提供离线自含HTML；本工具保证明示成员的字节和相对位置，不保证未列出的外部资源可用。

报告、附件、items及manifest都先在`_staging`准备，完整后一次提交。manifest的`attachments`只登记`relative_path`、`media_type`、实际`sha256`和`size_bytes`，不把原源路径当恢复依赖；删除源快照后仍可按同一相对位置恢复已列文件。每次`scan`／`context`／`reindex`均核缺失、尺寸和指纹；篡改或缺附件不会被静默重新索引为正常。

失败处理：

- 复制、格式检查、manifest登记或最终移动失败：没有已完成结果，报错；保留忽略的staging供核查，修复原请求资料后可用同一result_id重试，不删除已有结果或改ID绕过。staging不算已归档，进程崩溃遗留锁仍须先核进程状态。
- 完整结果已提交但索引失败：沿用`saved=true`、`catalog_updated=false`和警告；内容已保存，修复索引问题后`reindex`，不能重复归档覆盖。返回`saved=true`表示报告、明示附件及登记一同提交，附件具体清单以已保存manifest为准。
- `import`原件已提交而适配移动失败：仍按原import_id／result_id和元数据重试；已有原件及登记不覆盖，适配报告与附件作为完整一组提交。
- 附件缺失／篡改：保留原记录并定位问题，使用可信备份核对恢复或另建更正成果，不更改manifest哈希掩盖损坏。旧版无attachments的归档继续可读；旧0.1工具不提供新增附件复验，处理这类记录应使用支持本接口的版本。

`review`本轮仍仅保存其报告，不接附件字段；需完整技术快照时归档为新成果，并在回顾正文引用其结果身份。

## 持续回顾

取全部应回顾项，不只取最新报告。原模块提供本次允许的新资料，按原定义逐项核对；`review`保存新回顾报告、截止、证据及updates，关联原item_id。每项记录结果、原因和后续证据，不允许借更新修改原指标、期限或原文。若需要新的目标，另建新项并说明与原项关系。

`review.data_asof`会应用到本回顾更新的每个旧项。同一回顾混合财务、行情、暂停分钟等异步覆盖时，默认传`data_asof=null`，在逐项回顾正文及`reason`写实数据所属期、实际覆盖截止与缺口；或将可证具有相同数据截止的项拆为独立ID的多份回顾。不能用最新行情日期批量刷新旧财务／分钟项，也不把暂停分钟视为已补新数据。旧`item_id`和冻结判据保留，`generated_at`真实生成时间、`research_asof`本次信息截止与实际数据覆盖分开；追加回顾不自动给予`eligible`。这是现有协议下的填写规则，不增加逐项`data_asof`等未获支持的update字段。

保留失败、撤回、过期、未到期、未触发和无法判断；未被证伪不等于已证实。偏离原因按资料／计算、经营假设、技术结构、时间、执行和外部／无法归因分开，可多因并存。没有足够事实就不分配责任比例，不以事后叙事替代证据。

技术严格复盘先在回顾正文及`reason`记录五类问题：数据／计算、分析／条件、计划、执行、外部／未知，可多因并存；另分条件结果、计划采纳、执行事实与收益资格。支持“触发但执行受限”“用户明确未做”“执行未知”“部分执行”等不同事实；不把条件触发当成交，不把未交易当0收益。证据可知、触发、实际成交、反馈收到和P&L估值截止分开，精度不足保留未知。

`review.updates`仍严格只接受`item_id/status/reason/evidence_ids/current_use/current_use_reason/valid_until/review_due_at/invalidated_at`；不要添加未获验证的`issues`、`conflict_id`、新定义或任意feedback字段。现有item／evidence可保留某些额外键不代表已有强类型冲突模型。原证据ID仅在单份成果／请求内唯一，跨成果引用保留原result、证据ID、来源／快照指纹，并在本请求重新声明证据；不能用另一份档案裸ID证明已去重。

首版不自动运行预测检验或绩效模型。宿主依据原判据与新证据完成定性／数值回顾，工具负责不可覆盖保存、关联、期限检查及查询；不能把记录存储通过写成分析正确。

## 指定旧档导入

只导入用户指定source_file；原件副本进入imports，并生成标准适配成果及items。原研究／数据截止未知时可为空，存入undated并禁止直接获当前资格。original_generated_at需附能核实的原日期依据；适配生成时间和原输出日分开，后提取item冻结时间不倒填。

提取项只有原文中已有的命题和判据；不能用后来的结果反写旧预测。原件和更正保留。入库成功后再取context，确认旧关注项进入下次回顾。

## 计划与用户交易反馈

`plan`保存明确plan_id、版本、生效／有效时间及来源成果；研究情景不自动标用户已采纳。后续版本另存，旧版本继续可查。

`execution`接用户文字或脱敏表原件和标准trades。显式区分real／simulated、user_statement／user_supplied_record；每笔含成交时间及精度、方向、数量、价格、币种、费用（可未知）与计划版本分配。日期／归属不明先核对；同股或最近日期不能代替plan_id及具体版本，数量分配不得超额，同笔不得重复计量。

工具不计算P&L、不假设成交，不证明账户核验。缺反馈标执行未知；条件未触发与已触发未交易分开。部分平仓、未知成本／费用／汇率时保留缺口，已实现与未实现分列；需要计算时由宿主使用明确成本与费用口径复核，不能用原计划价当真实成交。

未触发、用户未做或执行未知只写回顾正文／原因，不向`execution`造空批次、0数量／0价格或假trade。真实成交可先用空`allocations`保留未匹配数量；如分配到计划才要求显式版本，所有分配总数不超过成交数量，同一版本不重复分配。

更正是整笔事实替换，以新trade_id和`correction_of_trade_id/correction_reason`追加，不能引用本请求生成时尚不可得的反馈，也不能跨证券／real与simulated或再次更正已被替换的旧节点。`context`保留全部原件，同时返回本次asof前已知的`superseded_trade_ids`；消费方应排除这些旧事实再评估，不能把旧记录和更正相加。该字段不推断未知重复、不计算P&L。

同源字节指纹、同证券及同real／simulated的普通重复导入被拒，显式更正另行保留。当前每批只接一个成交月份；同一跨月原件需先按月准备可核对的片段并保留原来源定位，不能把整表重复导入当成新月份。不同来源或新trade_id可能仍描述同笔真实成交，也可能是合法同价同量多笔；本工具不自动合并，未核实前保留待匹配，不直接累加为真实绩效。

## 失败与隐私

写入检查Git祖先、链接、路径范围和已有ID；使用写锁与staging，私有资料不回退到源码。根未配置、写锁冲突、原记录损坏或来源缺失都给具体限制，不声称自动记住。索引是可重建缓存，权威来自报告manifest／items、追加review、计划与成交记录。

无后台调度、账户接入、自动上云、整盘扫描或自改策略。没有真实数据时可测试虚构小样本，但测试资料不放正式私有证券档案里。

## 统一角色与可验证候选

`roles`由同包research_roles.py解析明示research-components/1及有限已知旧模式；context全历史不删，original_items保留冻结状态。研究角色、补充资料与未知分开；补充适配可在组件顶层声明`source_ref={security_id,import_id,original_sha256}`，绑定同一注册原件，路径由工具确定。原导入日可早于中断后适配生成日，两者不混写。原发布日期与封面报告日有分歧时两者保留。

S3平台只展示／回顾已有档案，不调用模型或刷新行情。可选verification-rules/1必须绑定原item_id、source_result_id、report_locator、definition摘要、明示metric／period／unit／basis／operator及有限target；verification-facts/1必须来源于正式研究、带证据公开时间且口径一致。禁止事后从自然语言抽阈值并倒签；回溯或晚定规则不计事前预测。机器结果只是待确认候选，定性项与原回顾原因保留原文。页面人工回顾只追加保守状态与理由；旧资格和窗口不自动延长。
